GET /health

서버 동작 여부를 확인합니다.

"status": "ok"

POST /api/stt/field

업로드한 음성 파일을 Whisper로 텍스트 변환합니다. 입력 폼의 각 필드에 음성 입력 기능을 구현할 때 사용합니다.

Request — multipart/form-data

필드타입설명
audio_fileFile필수음성 파일. webm · mp4 · mp3 · wav 등
field_typestring필수era · place · characters · topic 중 하나
languagestring선택언어 코드. 기본값 ko-KR

Response — 200 OK

{
  "stt_text":     "조선 시대",        // Whisper 원문
  "parsed_value": "조선 시대",        // 정규화된 값 (이 값을 사용하세요)
  "confidence":   0.91               // 0.0 ~ 1.0
}

POST /api/runs

동화 생성 작업을 생성하고 백그라운드 파이프라인을 시작합니다.

ℹ️

파이프라인 구조
Stage 1 (LLM): 마스터 서버에서 story.json 생성
Stage 2 (TTS): 마스터 서버에서 음성 생성 후 VRAM 해제
Stage 3 (IMAGE): 마스터 서버에서 1280x720 이미지 9장 생성 후 VRAM 해제

Request — application/json

{
  "era_ko":        "조선 시대",
  "place_ko":      "한양의 작은 서당",
  "characters_ko": "호기심 많은 아이와 말하는 호랑이",
  "topic_ko":      "서로를 믿는 우정"
}

Response — 201 Created

{ "run_id": "20260429_173423_d118aa" }

이 run_id는 이후 모든 조회 API에서 사용합니다.

최상위 필드

필드타입설명
run_idstring작업 ID
statusstringQUEUED / RUNNING / DONE / FAILED
stagestringLLM / TTS / IMAGE

scenesarray씬 목록. LLM 완료 후 4개 고정

cover 구조

cover는 SceneScenarioInfo 타입이며 scenarios 2개만 포함합니다.

cover · index 0
표지 이미지
image_url = cover.png
cover · index 1
제목 낭독
msg = 동화 제목
audio_url = cover.wav

scenes[].scenarios 구조 (씬당 4개)

index 0
첫 번째 이미지
image_url = scene_NN_img_01.png
delay = N초 대기
index 1
내레이션
msg = 내레이션 텍스트
audio_url = scene_NN_0.wav
delay: 0 = 오디오 완료까지 대기
index 2
두 번째 이미지
image_url = scene_NN_img_02.png
delay = N초 대기
index 3 ▲ 변경
대사
msg = 대사 텍스트
audio_url = scene_NN_1.wav
(비어 있으면 자막만 표시)
💡

delay 계산: round(scene_NN_0.wav 재생시간 ÷ 2). 최솟값 1초.

  "cover_prompt": "children's book cover, soft watercolor painting, ...",
  "scenes": [

      "scene_no": 1,

GET /api/runs/{run_id}/images/{filename}

생성된 PNG 이미지를 반환합니다.

응답 형식image/png
캐시Cache-Control: no-store

파일명 패턴

cover.png
scene_01_img_01.png  ~  scene_04_img_02.png
처리 위치파일명
마스터 서버cover.png, scene_01_img_01.png ~ scene_04_img_02.png

GET /api/runs/{run_id}/audio/{filename}

생성된 WAV 오디오를 반환합니다.

응답 형식audio/wav
포맷RIFF PCM, 비압축, 모노
캐시Cache-Control: no-store

파일명 패턴

cover.wav               ← 표지 제목 낭독
scene_01_0.wav          ← 씬 1 내레이션
scene_01_1.wav          ← 씬 1 대사
scene_02_0.wav  ~  scene_04_0.wav   (각 씬 내레이션)
scene_02_1.wav  ~  scene_04_1.wav   (각 씬 대사)
⚠️

이전 버전과 달리 씬 오디오가 scene_01.wav 형태의 단일 파일이 아닌, 내레이션(_0)과 대사(_1)로 분리됩니다.

클라이언트 구현 흐름

1. POST /api/runs                    → run_id 수신
2. GET  /api/runs/{id}/events        SSE 연결
   + GET  /api/runs/{id}             1500ms 폴링 병행
3. scenes.length === 4 감지          → LLM 완료, 씬 카드 4개 렌더링
4. scene.status === "End" 감지       → 해당 씬 재생 가능
5. status === "DONE"                 → 전체 완료

진행률 계산 (앱 기준)

분류항목개수
스토리story_title 1 + scenes 45
이미지cover 1 + 씬 이미지 2×49
오디오cover 1 + 씬 내레이션 45
합계19

씬 대사 오디오(scene_NN_1.wav) 4개는 진행률 계산에서 제외됩니다.

표지 URL 추출

const scenarios   = data.cover?.scenarios || [];
const coverImage  = (scenarios.find(s => s.index === 0) || {}).image_url || '';
const coverAudio  = (scenarios.find(s => s.index === 1) || {}).audio_url || '';

씬 재생 흐름

async function playScene(scene) {
  for (const step of scene.scenarios) {
    if (step.image_url) {
      showImage(step.image_url);
      await wait(step.delay * 1000);          // delay초 대기
    }
    if (step.audio_url) {
      showSubtitle(step.msg);
      await playAudio(step.audio_url);        // 오디오 완료까지 대기
    }
    if (!step.image_url && !step.audio_url && step.msg) {
      showSubtitle(step.msg);                 // index 3: 대사 자막만
    }
  }
}
